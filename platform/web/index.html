        Your spec passed the readiness check, so the build launcher created your public GitHub repository and started a builder: a container on AWS. In it, Claude, the coding agent running on Amazon Bedrock, writes your app's files from the workshop's template. It can only work on files in its own folder and read public web pages; it holds no AWS keys. The builder checks the files and saves them to your repository in a few commits. Then the deployer checks them again and publishes exactly what GitHub holds on the workshop's site. This page asks for news every 2 seconds.

                  Behind the scenes

                  Each change goes round this loop. A safety check reads your request first (an unusual one waits until your facilitator has looked at it); then Claude, the AI model on Amazon Bedrock, writes the next version of your spec and a short "What changes" list. Not this one sends you back to the box; when you press Build this change, the readiness check runs and your build joins the queue. The coding agent starts from your app's files on GitHub and changes only what the list says, the builder saves them in one commit, and the deployer checks them and publishes them at the same address and QR code. A change counts once its build is queued; a declined request or Not this one does not count.
